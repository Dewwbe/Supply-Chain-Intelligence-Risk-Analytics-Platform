# Anomaly Detection (Phase 8)

Generated by `notebooks/08_anomaly_detection.ipynb` via
`src/anomaly_detection/`.

- `anomalies.csv` — every `severity == 'High'` anomaly, across all 3
  methods (IQR, Z-score, Isolation Forest) and all 5 domains (daily
  sales, inventory changes, shipment delays, transport costs, supplier
  lead times), ranked by `anomaly_score` descending: `anomaly_id, date,
  entity, metric, method, expected_value, actual_value, anomaly_score,
  severity`.

The pipeline (`detect_all()`) flags 72k+ points across all severities in
one full-history pass — a demonstration of what each method catches, not
a production alerting design (see the notebook's §5 for what that would
need to change). Only the High-severity subset is persisted here, the
same small-curated-summary convention as every other report in
`reports/`; the Low/Medium counts are still visible via the notebook's
severity breakdown in §2. Thresholds are documented in
`src/anomaly_detection/detectors.py`, not implied. Regenerate after any
change to the underlying `fact_sales`/`fact_inventory`/`fact_shipments`
data (i.e. after `make etl`).
